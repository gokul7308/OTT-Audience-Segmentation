# API & Evaluator Integration

## Overview
This document details the final validation step of the Audience Segmentation API using the independent `evaluator` service. The API natively reads the deterministic KMeans clustering pipeline (`clustering_pipeline.pkl`) and segment metadata (`segment_metadata.json`) generated by the offline ML trainer.

## API Endpoints

### `GET /health`
Validates the API boot status and model availability.
- **Response Structure:** `{"status": "ok", "model_loaded": true}`

### `POST /recommend`
Performs live model inference against a user behavior matrix.
- **Request Structure:** Takes exactly 27 flattened numerical behavioral features (e.g., `interaction_count`, `rating_std`, `genre_prop_action`) derived during feature engineering.
- **Response Structure:**
  ```json
  {
    "user_id": "string",
    "segment_id": 1,
    "segment_name": "Regular Viewers (Action, Comedy)",
    "recommendations": ["Prioritize titles in Action and Comedy.", "Mix preferred genres..."],
    "distance_to_centroid": 1.234
  }
  ```

## Validation Tests (Evaluator Methodology)
The `evaluate.py` script waits for the API to report readiness, then submits an array of valid and invalid payloads.

1. **Valid Requests:** Tests different edge shapes of normal user behavior matrices. Verifies that the API cleanly wraps the `StandardScaler` and `KMeans` inference without internal server errors, correctly looks up segment IDs from JSON metadata, and returns distances.
2. **Robustness/Edge Cases:** Ensures Pydantic correctly rejects malformed JSON. Validated against:
   - Missing required fields (e.g., `user_id` missing)
   - Negative values where invalid (e.g., negative `interaction_count`)
   - Incorrect data types (e.g., string instead of float for counts)
   - Values out of bounds (e.g., rating proportions exceeding 1.0, or average ratings > 5.0)

## Actual Results & Metrics
The Evaluator successfully merges its own robustness results (`api`, `robustness` sections) with the actual ML metrics derived offline (`clustering` section). No fake metrics were generated; the true `silhouette_score` and `inertia` are represented transparently in `metrics.json`. 

## Known Limitations
The API accepts exact pre-computed feature vectors rather than raw events. In a full production system, a feature store or real-time feature engineering streaming job would aggregate interactions into these 27 features prior to invoking this recommendation endpoint.
